Abstract
Software development projects involve a large number of tasks that must be planned, assigned,
monitored, and completed within limited time and resource constraints. As project size in-
creases, project teams frequently face diﬀiculty in determining which task should receive at-
tention first. Conventional project management systems generally provide features for task cre-
ation, assignment, status tracking, deadlines, and workflow visualization; however, the actual
prioritization of tasks often remains dependent on manual judgement. Manual prioritization can
become diﬀicult when several tasks have different deadlines, business impacts, dependencies,
complexity levels, and workload implications. This creates a need for a project management
system capable of providing systematic and explainable support for task-level decision making.
The proposed project, AI-Powered Project Management System with Automatic Task Pri-
oritization, aims to develop a web-based project management platform that integrates project
planning, task management, Kanban-based workflow visualization, automatic task prioritiza-
tion, AI-assisted task analysis, risk identification, and workload analysis within a unified system.
The proposed system will allow users to create projects, manage team members, define tasks,
assign responsibilities, specify deadlines, estimate effort, identify dependencies, and monitor
project progress through a visual Kanban interface.
The central component of the proposed system is an Automatic Task Prioritization Engine.
Instead of depending only on manually selected priority labels such as Low, Medium, or High,
the proposed engine will analyse multiple task-related factors. These factors include deadline
urgency, business impact, dependency impact, team workload, and task complexity. The fac-
tors will be normalized and combined using a weighted scoring model to generate a measurable
priority score. The system will also provide a human-readable explanation showing why a par-
ticular task received its priority, thereby improving transparency and interpretability.
An AI-assisted analysis layer will complement the deterministic priority engine. It will anal-
yse task descriptions and project context to suggest task complexity, estimated effort, required
skills, possible risks, dependencies, and smaller actionable subtasks. The AI layer will act as
a decision-support component rather than replacing the deterministic prioritization mechanism.
This separation is intended to make the system easier to evaluate and suitable for academic
demonstration.
The proposed system will follow an iterative Agile development methodology. The core project
management and Kanban functionality will be developed first, followed by the prioritization en-
gine, AI-assisted analysis, risk detection, workload analysis, and testing. The expected outcome
is a functional and lightweight project management prototype that can help software teams un-
derstand not only the current status of their tasks but also which tasks should receive attention
first and the factors responsible for that recommendation.

Introduction
2.1 Background
Project management is an essential activity in software development because the successful com-
pletion of a software product depends not only on programming but also on effective planning,
organization, resource allocation, communication, monitoring, and decision making. A soft-
ware project is normally divided into multiple activities or tasks that may involve different team
members, deadlines, technical requirements, dependencies, levels of complexity, and business
priorities. As a project progresses, the importance of individual tasks may change according
to deadlines, completed dependencies, emerging risks, resource availability, and changes in
project requirements.
In a small project, a project manager or development team can often prioritize tasks manually
by considering experience and immediate requirements. However, manual decision making
becomes more diﬀicult as the number of tasks increases. A team may have several high-priority
tasks, but not all of them can necessarily be executed simultaneously. Some tasks may have an
approaching deadline, while another task may have a high business impact. A third task may
block several other activities because it is a dependency. Similarly, a developer may already be
assigned to multiple tasks, making workload an important consideration.
Traditional project management systems have addressed many aspects of this problem by pro-
viding centralized task repositories, dashboards, calendars, workflow boards, notifications, and
reporting mechanisms. These systems improve visibility and coordination. However, the re-
sponsibility for deciding which task should be executed next may still remain with the project
manager or individual team members. Consequently, the system may store large amounts of
project information without transforming that information into a clear and explainable task-level
recommendation.
The concept of Agile software development provides an important foundation for addressing
this challenge. Agile methods emphasize iterative development, continuous feedback, adapta-
tion, customer value, and frequent delivery. Prioritization is an important part of Agile planning
because teams must decide which requirements or work items should be addressed first. Re-
quirements prioritization research has investigated numerous approaches including value-based
techniques, ranking techniques, pairwise comparison, voting, analytical methods, optimization,
and machine-learning-based techniques.
Kanban is another important concept relevant to the proposed system. Kanban provides a vi-
sual representation of workflow in which work items move through different states. A typical
software Kanban board may contain stages such as Backlog, To Do, In Progress, Review, and
Done. Visual workflow makes the current state of work easier to understand and can help teams
identify bottlenecks. Research on Kanban in software engineering has systematically examined
its benefits, challenges, practices, and research opportunities. However, a Kanban board primar-

2.2 Task Prioritization in Software Development
Task prioritization refers to the process of determining the relative order in which tasks should
be addressed. It is closely related to requirements prioritization but is broader in the context
of project execution because a task may represent a feature, bug fix, technical activity, testing
activity, documentation task, infrastructure task, or other project activity.
Research has demonstrated that prioritization is a complex decision-making activity. Karlsson
and Ryan proposed a cost-value approach in which requirements are evaluated according to their
relative value and cost. Karlsson, Wohlin, and Regnell evaluated multiple requirements prior-
itization methods and highlighted both the usefulness and scalability challenges of structured
prioritization techniques. Later systematic reviews further demonstrated that requirements pri-
oritization has developed into a large research area containing numerous techniques and criteria.
Achimugu et al. conducted a systematic literature review of software requirements prioritiza-
tion research and identified several commonly used prioritization techniques. Their review also
highlighted challenges such as scalability, changing requirements, stakeholder coordination, and
dependency handling. Similarly, Pitangueira et al. investigated requirements selection and pri-
oritization using Search-Based Software Engineering approaches and observed the importance
of release planning, optimization, risks, and uncertainties.
More recent empirical research has focused on the actual evaluation of prioritization techniques.
Bukhsh, Bukhsh, and Daneva reviewed 102 papers covering requirements prioritization ap-
proaches and their empirical evaluation. Their work shows that modern prioritization methods
increasingly employ fuzzy logic, optimization, and machine learning while also highlighting
scalability and empirical validation as important concerns.
These findings are relevant to the proposed project because a practical project management
system should not depend on a single factor such as manually selected priority. Instead, multiple
project factors should contribute to the recommendation.
2.3 Importance of Multiple Criteria
A software task can have different levels of importance depending on project context. Deadline
urgency is one important factor. A task with a deadline approaching within a short period
may need immediate attention. However, deadline alone is insuﬀicient. A low-impact task due
tomorrow may not necessarily be more important than a critical business task due next week.

Business impact is therefore another important criterion. A task related to a core project feature,
customer requirement, security issue, or important deliverable may have greater significance
than a minor enhancement. Research in value-based requirements prioritization supports the
use of business or stakeholder value as an important prioritization criterion.
Dependencies represent another critical dimension. If Task B cannot be completed until Task
A is completed, then the status of Task A affects the overall project flow. A task that blocks
several downstream tasks may deserve additional attention even if its individual business value
is moderate.
Team workload also influences practical task prioritization. A theoretically important task may
not be immediately executable if the assigned developer is already overloaded. Conversely,
assigning additional high-priority tasks to an overloaded team member can create delays and
bottlenecks.
Complexity and estimated effort are also relevant. A complex task may require more preparation,
additional resources, or earlier initiation. A team may therefore need to identify complex tasks
earlier than simple tasks even when their deadlines are similar.
The proposed project combines these factors into a unified scoring mechanism. The purpose is
not to claim that one universal formula is optimal for all software projects. Instead, the formula
represents a transparent prototype model that can be tested and refined using representative
project data.
2.4 Artificial Intelligence in Project Management
Artificial Intelligence has increasingly been investigated as a technology for supporting project
management. Research reviews have identified applications of AI in project planning, schedul-
ing, forecasting, risk management, performance monitoring, decision support, resource alloca-
tion, and uncertainty management.
AI can be useful when a project contains large amounts of textual or structured information. For
example, a task description may contain information about functionality, technical requirements,
dependencies, risks, or expected effort. An AI-assisted component can analyse this description
and convert unstructured information into structured suggestions.
However, the use of AI in project management also introduces challenges. AI-generated recom-
mendations may not always be transparent, consistent, or appropriate for every project context.
Data quality, explainability, integration, empirical validation, and human oversight are therefore
important considerations.
For this reason, the proposed project separates AI-assisted analysis from the core prioritization
calculation. The priority score will be produced through a deterministic multi-factor model.
AI will assist in understanding task descriptions, suggesting subtasks, estimating complexity,
identifying risks, and providing supporting recommendations.

2.5 Need for an Integrated System
Existing research demonstrates strong individual contributions in requirements prioritization,
task prioritization, Kanban, Agile project management, and AI-enabled project management.
However, these research areas are often studied separately.
A software team may therefore have a Kanban board for workflow visualization, a task manage-
ment tool for assignments, separate reporting dashboards, and manual processes for deciding
priority. The proposed project explores the integration of these activities into one lightweight
platform.
The intended workflow is:
Task Creation →Task Analysis →Priority Calculation →Explanation →Kanban
Decision Support
The system will not automatically force a team to follow every recommendation. Instead, the
priority score will act as decision support. The project manager or team member will remain
able to inspect the factors, modify task information, and make the final decision.
2.6 Research Motivation
The research motivation arises from four major observations.
First, task prioritization is a recurring activity in software development and becomes more dif-
ficult when projects contain numerous tasks and constraints.
Second, research on requirements and task prioritization has demonstrated the usefulness of
multi-criteria approaches, but different approaches address different contexts and often have
scalability or evaluation limitations.
Third, Kanban provides a strong visual mechanism for workflow management but does not itself
provide an automatic multi-factor prioritization mechanism.
Fourth, AI-enabled project management research shows increasing potential for decision sup-
port, risk analysis, forecasting, and planning, while recent studies continue to identify challenges
concerning empirical validation, integration, transparency, and practical implementation.
Therefore, the proposed research investigates a practical combination of these concepts within
a single academic prototype.

2.7 Scope of the Proposed Work
The proposed system will focus primarily on software project management. The minimum func-
tional scope will include user authentication, project creation, team management, task manage-
ment, task assignment, deadlines, dependencies, Kanban workflow, automatic priority calcu-
lation, priority explanations, AI-assisted task analysis, risk indicators, workload analysis, and
basic project analytics.
The proposed prototype will be lightweight and suitable for local development and academic
demonstration. The system will not depend on heavy enterprise infrastructure. The architecture
will be modular so that additional capabilities can be introduced in future versions.
The system will use a modern full-stack web architecture consisting of a React-based frontend,
Node.js and Express.js backend, and MongoDB database. AI-assisted functionality will be
designed with an abstraction layer so that a local or external AI provider can be used without
changing the main project-management logic.
2.8 Significance of the Project
The significance of the proposed project lies in transforming project data into actionable decision-
support information. Instead of simply displaying that a project contains twenty tasks, the sys-
tem attempts to answer a more useful question: Which task should the team consider first, and
what factors explain that recommendation?
The project also provides an opportunity to combine several areas of Computer Science and
Full Stack Development, including frontend development, backend API development, database
design, authentication, software engineering, Agile project management, decision-support sys-
tems, Artificial Intelligence, data analysis, testing, and system integration.
From an academic perspective, the system provides a clear problem, measurable inputs, deter-
ministic processing, AI-assisted functionality, and possible evaluation criteria. This makes the
project suitable for experimental demonstration and future extension.
2.9 Summary of Introduction
In summary, modern software projects require continuous prioritization because tasks differ
in urgency, business value, dependencies, complexity, and resource requirements. Existing re-
search has provided several approaches to requirements and task prioritization, while Kanban
provides effective workflow visualization and AI research provides opportunities for intelligent
project decision support. The proposed project brings these ideas together through an integrated
project management system.
The main research focus is therefore the design of an explainable automatic task prioritization
mechanism supported by a Kanban-based project management interface and an AI-assisted task
analysis layer. The system is intended to help project teams organize work, identify important

Problem Analysis / Literature Review
3.1 Problem Identification
Based on the study of existing research and project management practices, the following prob-
lems have been identified:
1. Conventional project management systems primarily provide mechanisms for creating,
assigning, organizing, and tracking tasks, while the decision of which task should be
executed first may remain manual.
2. Kanban boards improve workflow visibility but do not inherently calculate a task pri-
ority based on multiple project factors.
3. Manual prioritization becomes diﬀicult when a project contains many tasks with dif-
ferent deadlines, business impacts, dependencies, complexities, and workloads.
4. A task that is individually important may not necessarily be the task that should be
executed first if another task blocks multiple downstream activities.
5. Developer workload is often considered separately from task priority, even though re-
source availability can influence practical execution.
6. Existing requirements prioritization techniques often address requirements selection
or release planning rather than continuous task-level prioritization during project exe-
cution.
7. Research on software task prioritization has historically concentrated heavily on spe-
cialized categories such as bugs, issues, and pull requests.
8. AI-enabled project management research demonstrates significant potential but also
identifies concerns regarding explainability, integration, data quality, validation, and
human oversight.
9. There is a need for a lightweight integrated prototype that demonstrates automatic task
prioritization together with workflow visualization and AI-assisted task analysis.
3.2 Problem Statement
In software development projects, teams continuously manage tasks having different deadlines,
business impacts, dependencies, complexities, estimated efforts, and resource requirements.
Conventional project management systems provide facilities for task organization and workflow
visualization, but the process of determining which task should receive attention first frequently
depends on manual judgement.
As the number of tasks increases, manual prioritization may become inconsistent, time-consuming,
and diﬀicult to update. Project managers may need to simultaneously consider deadline urgency,
business importance, dependencies, team workload, and complexity. A change in any one of
these factors may affect the relative importance of tasks.

3.5 Analysis of the Literature
The reviewed literature demonstrates that prioritization has been studied from several perspec-
tives. Early research focused on structured requirements prioritization techniques such as cost-
value analysis and analytical decision methods. These approaches established the importance
of comparing multiple attributes rather than relying solely on a single priority label.
Subsequent research expanded the field through systematic reviews and Search-Based Software
Engineering. These studies demonstrate that requirements prioritization can involve optimiza-
tion, stakeholder preferences, risk, uncertainty, dependencies, and resource constraints. How-
ever, many approaches are designed specifically for requirements selection or release planning.
Agile research further demonstrates that business value, complexity, dependencies, and other
contextual factors influence prioritization decisions. This provides strong theoretical support
for the proposed multi-factor task-priority model.
Research on task prioritization in software development provides an especially important obser-
vation. Bug, issue, and pull-request prioritization represent major categories within the existing
literature. This means that automated ranking is already an established research direction, but
there remains room for broader task-level project management systems that integrate different
task attributes and project context.
Kanban research provides the workflow foundation for the proposed system. A Kanban board
allows project teams to visually track the current state of work. The proposed system extends
this idea by associating task priority information with the workflow.
The AI project management literature demonstrates that Artificial Intelligence can assist with
planning, forecasting, risk management, monitoring, and decision support. At the same time,
recent systematic reviews identify challenges related to transparency, empirical validation, inte-
gration, data quality, and organizational adoption.
Therefore, the proposed project does not claim to introduce an entirely new theory of prioriti-
zation. Instead, it aims to provide an integrated, explainable, lightweight academic system that

The proposed project positions itself as an integrated decision-support prototype rather than a
replacement for professional project managers. The system will calculate and display a priority
recommendation, but the final decision will remain under human control.

Proposed Methodology
4.1 Methodology Overview
The proposed system will follow an iterative Agile software development methodology. De-
velopment will be performed incrementally, beginning with requirements analysis and system
design, followed by core project management features, Kanban workflow, automatic prioritiza-
tion, AI-assisted analysis, risk and workload analysis, and final evaluation.
The methodology is designed so that the core application remains functional even if the AI-
assisted component is unavailable. This ensures that the project does not become completely
dependent on an external AI service.
The major stages are:
1. Requirement analysis and literature study.
2. System architecture and database design.
3. User authentication and role management.
4. Project and team management.
5. Task management.
6. Kanban workflow development.
7. Automatic task prioritization.
8. AI-assisted task analysis.
9. Risk and workload analysis.
10. Project analytics.
11. Testing and evaluation.
12. Documentation and demonstration.

The purpose of the Kanban board is not only to show task status but also to provide a visual
interface through which priority recommendations can be interpreted in the context of current
project work.
4.6 Automatic Task Prioritization Engine
The central technical component of the proposed system is the Automatic Task Prioritization
Engine.
The initial priority score will be calculated using:
P = 0.30U + 0.25I + 0.20D + 0.15W + 0.10C
(1)
where:
• P = Final Priority Score.
• U = Deadline Urgency Score.
• I = Business Impact Score.
• D = Dependency Impact Score.
• W = Workload Factor.
• C = Complexity Score.
All factors will be normalized to a scale of 0–100.
The weights represent the initial design of the proposed academic prototype. They are not
claimed to be universally optimal. Their purpose is to provide a transparent and measurable
baseline that can be evaluated during testing.

4.7 Deadline Urgency
Deadline urgency will represent how close a task is to its deadline.
A simplified conceptual mapping can be:
• Very distant deadline – low urgency.
• Approaching deadline – moderate urgency.
• Near deadline – high urgency.
• Overdue deadline – critical urgency.
The actual implementation will calculate urgency using task deadline and current date/time.

4.9 Dependency Impact
Dependency impact will measure how strongly a task influences other tasks.
For example, a task that blocks multiple downstream tasks can receive a higher dependency
score. A task without important dependencies may receive a lower score.
The proposed dependency analysis may consider:
• Number of dependent tasks.
• Whether dependent tasks are critical.
• Whether the task is blocking progress.
• Whether the dependency affects a deadline.
